# AGENTS.md — инструкция для ИИ-ассистентов

Этот файл читают ИИ-агенты (Claude Code, Cursor, GigaCode и др.) перед любой правкой проекта.
Он задаёт контекст, правила и границы, чтобы агенты не ломали безопасность и стиль.

## Что это за проект
«Деканат+» — концепт личного кабинета студента СПбГУ для конкурса «Цифровой деканат будущего».
Это **не официальный сервис университета**. Все люди, оценки, номера и документы — вымышленные.

Главная идея: студент открывает кабинет и сразу видит свой день — «линию дня» в стиле схемы метро,
где пары — станции, а переезд между корпусами (Васильевский, Смольный, Петергоф) — пересадка
с предупреждением, успевает ли он за перерыв.

## Стек
- Сервер: Node.js 22, Express, встроенный SQLite (`node:sqlite`), bcryptjs, helmet, express-rate-limit, qrcode.
- Клиент: один файл `public/app.js` без фреймворков, хеш-маршруты (`#/schedule`, `#/requests/5`).
- Шрифты Onest и Unbounded (лицензия OFL) лежат в `public/fonts` — без запросов к Google.

## Карта файлов
| Файл | За что отвечает |
|---|---|
| `server.js` | Все HTTP-маршруты, сессии, проверка ролей и владельца данных |
| `src/db.js` | Схема базы данных |
| `src/seed.js` | Вымышленные демо-данные и «живые» изменения расписания на текущую неделю |
| `src/schedule.js` | Сборка недели, применение переносов, расчёт пересадок между корпусами |
| `src/catalog.js` | Каталог справок и заявлений + серверная проверка полей формы |
| `src/assistant.js` | Помощник «Спроси деканат»: база знаний + необязательный ИИ через ключ на сервере |
| `public/app.js` | Все экраны: Сегодня, Расписание, Учёба, Заявки, Уведомления, Помощник, Профиль, кабинет сотрудника |
| `public/styles.css` | Визуальная система «Петербург» (токены в `:root`) |

## Правила безопасности (нарушать нельзя)
1. **Любой запрос к данным студента фильтруется по `req.user.id` на сервере.** Никогда не доверять id из адреса без проверки владельца. Пример — `ownRequest` в `server.js`: `WHERE id = ? AND user_id = ?`. Чужая запись → 404, без подсказок.
2. Пароли — только bcrypt-хеш. Токен сессии в базе — только SHA-256. Cookie — `HttpOnly`, `SameSite=Lax`, `Secure` в продакшене.
3. Ключи (ИИ и любые другие) — только в переменных окружения на сервере. Никогда в `public/`, никогда в коде, никогда в ответах API.
4. Изменяющие запросы (`POST`, `PATCH`) требуют заголовок `X-Requested-With: dekanat` — защита от подделки запросов.
5. Сервер принимает только поля форм, описанные в `src/catalog.js`, с ограничением длины.
6. Весь пользовательский текст на клиенте выводится через `esc()`. Не использовать `innerHTML` с сырыми данными.
7. Только вымышленные данные. Не добавлять реальные ФИО, номера зачёток, логотип СПбГУ.

## Правила интерфейса
- Мобильная версия первична: всё должно работать от 360 px. Нижняя панель — 5 разделов, не больше.
- У каждого экрана есть три состояния: загрузка (скелетон), ошибка (что случилось + «Повторить»), пусто (что сделать дальше).
- Тексты — от лица интерфейса, простыми словами, без извинений. Кнопка называет действие: «Отправить заявку», тост — «Заявка отправлена».
- Цвета: охра `--ochre` — только изменения и переносы, кирпичный `--brick` — только отмены и ошибки. Цвет корпуса = цвет ветки метро рядом с ним.
- Иконки рисуем сами в объекте `P` в `app.js` (обводка 2px, viewBox 24).

## Как проверить свою правку
```bash
npm start                       # http://localhost:3000
bash scripts/e2e.sh             # проверки безопасности и сценариев
```
Демо-аккаунты: `anna / Anna2026!`, `maxim / Maxim2026!`, `staff / Staff2026!`.
Чтобы сбросить демо-данные — удалите папку `data/` и перезапустите сервер.
