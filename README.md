# Деканат+ — цифровой деканат будущего (концепт)

Рабочий прототип личного кабинета студента СПбГУ для конкурса «Цифровой деканат будущего» (номинация «Вайб-кодинг»).
**Не официальный сервис СПбГУ.** Все данные вымышленные, прототип не подключён к системам университета.

## Тестовые аккаунты

|---|---|---|---|

| Студент бакалавриата, ПМ-ПУ | `maxim` | `Maxim2026!` | Петергоф, просроченное задание, предметы в зоне риска, отклонённое заявление |
| Сотрудник учебного отдела | `staff` | `Staff2026!` | Обработка заявок, публикация объявлений |

Данные двух студентов полностью разделены: Анна не может открыть заявку Максима, даже подставив её номер в адрес.

## Что умеет кабинет
- **Сегодня** — текущая или следующая пара крупно, «линия дня» как схема метро с пересадками между корпусами, важные объявления, дедлайны на неделю, статусы заявок.
- **Расписание** — неделя, переносы и замены аудиторий отмечены охрой, отмены — кирпичным, список всех изменений недели.
- **Учёба** — баллы по каждой дисциплине, сколько ещё нужно до «отлично» или зачёта, прогноз стипендии, процент «отлично» для красного диплома, зачётка.
- **Заявки** — 10 видов справок и заявлений, статус как трекинг доставки, электронная справка с QR-кодом проверки подлинности.
- **Уведомления** — объявления для всех, факультета, группы и лично; отдельная вкладка дедлайнов.
- **Помощник «Спроси деканат»** — отвечает на вопросы о правилах и сразу ведёт к нужной заявке.
- **Кабинет сотрудника** — очередь заявок, смена статуса с комментарием (студент сразу получает уведомление), объявления группам.

## Запуск локально
Нужен Node.js 22+.
```bash
npm install
npm start          # http://localhost:3000
```

## Деплой (открывается из России без VPN)
Подойдёт любой хостинг с Docker или Node.js: Timeweb Cloud Apps, Yandex Cloud Serverless Containers, Amvera, Selectel.

**Timeweb Cloud → Apps (проще всего):**
1. Залейте код в GitHub или GitVerse.
2. В Timeweb Cloud: «Apps» → «Создать» → «Dockerfile» → подключите репозиторий.
3. Переменные окружения: `NODE_ENV=production`. Для ИИ-помощника (необязательно): `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`.
4. Подключите постоянный диск в папку `/app/data`, чтобы заявки сохранялись при перезапуске.
5. После деплоя откройте выданный адрес `https://…` и войдите под тестовым аккаунтом.

**Через Docker на любом сервере:**
```bash
docker build -t dekanat .
docker run -d -p 80:3000 -e NODE_ENV=production -v dekanat-data:/app/data dekanat
```

## Безопасность простыми словами
- Пароли хранятся только в виде bcrypt-хеша — даже владелец базы не узнает пароль.
- После входа браузер получает случайный «пропуск» в защищённой cookie, недоступной скриптам. В базе хранится только его отпечаток (SHA-256).
- Каждый запрос сервер проверяет по владельцу: чужую заявку, справку или оценки не открыть, подставив другой номер.
- Студент не может открыть разделы сотрудника — сервер проверяет роль.
- Подбор пароля блокируется после 10 попыток за 15 минут.
- Ключ ИИ хранится только в переменных окружения сервера. В коде и в браузере его нет.
- Заголовки безопасности (CSP, запрет встраивания в чужие сайты) включены через helmet.

## Масштабирование
Сервер не хранит состояние в памяти: сессии лежат в базе, поэтому можно запускать несколько копий за балансировщиком.
Схема написана на переносимом SQL — при росте нагрузки SQLite меняется на PostgreSQL без переделки логики.
