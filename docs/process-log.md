# Журнал разработки — материал для отчёта

Сюда записываются этапы, промпты и ошибки ИИ. Из этого журнала собирается PDF-описание процесса для жюри.
Дополняйте его на каждом следующем этапе (дизайн в других нейросетях, опрос однокурсников, деплой, видео).

## Инструменты
| Инструмент | Для чего |
|---|---|
| Claude (Anthropic), чат с агентными инструментами | Концепция, архитектура, весь код сервера и интерфейса, тестовые данные, автотесты, скриншоты, документация |
| Headless Chrome + Playwright (запускал ИИ) | Скриншоты на ширине 360 px и 1366 px, поиск визуальных ошибок |
| _добавить_ | _например: нейросеть для картинок, опрос однокурсников в Яндекс Формах, хостинг_ |

## Этап 1. Постановка задачи и концепция
**Промпт:** загружен бриф конкурса целиком + «это номинация вайб-кодинг», «сможешь помочь?».
**Результат:** ИИ выделил ключевые требования (рабочий прототип, безопасность, доступ из РФ, отчёт = половина оценки) и предложил концепцию под СПбГУ:
- проблема: корпуса разбросаны по городу, информация — по разным системам;
- главная идея: экран «Мой день» вместо папки разделов;
- фишки: пересадки между корпусами, прогноз стипендии и красного диплома, справка с QR, ИИ-помощник, кабинет сотрудника.

## Этап 2. Архитектура
**Промпт:** «давай сразу начнёшь».
ИИ составил план задач (сервер → данные → интерфейс → документы → проверка) и выбрал стек:
Node.js + Express + SQLite. Обоснование: минимум зависимостей, быстро разворачивается, схема переносится в PostgreSQL.

## Этап 3. Дизайн-система
ИИ сформулировал направление «Петербург»: невская синь, гранит, туман, охра фасадов.
Ключевой визуальный приём — расписание как линия метро; цвет корпуса = цвет ветки
(Василеостровская — зелёная, Чернышевская — красная, Петергоф — фиолетовый).
Шрифты Onest и Unbounded (российские, лицензия OFL) скачаны на сервер — без зависимости от Google.
Логотип — собственный: разведённый мост и плюс.

## Этап 4. Сервер и безопасность
Реализовано: вход с bcrypt, сессии в защищённой cookie, проверка владельца в каждом запросе,
роли «студент» и «сотрудник», ограничение попыток входа, защита от подделки запросов, CSP-заголовки.

## Этап 5. Интерфейс
7 экранов студента + 2 экрана сотрудника, у каждого — состояния загрузки, ошибки и пустоты.

## Этап 6. Проверка и работа с ошибками ИИ
ИИ сам сделал скриншоты на телефоне и нашёл свои ошибки:

| Что было не так | Как нашли | Как исправили |
|---|---|---|
| Иконки в списке дедлайнов растянулись на пол-экрана | Скриншот 360 px | Добавлен размер для иконок в строках списка |
| Время текущей пары «13:40–15:15» переносилось на две строки и наезжало на декор | Скриншот 360 px | Отдельный уменьшенный размер для диапазона времени, декор перенесён вниз |
| Баллы по предметам не сходились с суммой заданий, полоса «осталось набрать» была почти пустой | Проверка логики на экране «Учёба» | Баллы считаются из заданий, добавлена часть «экзамен/зачёт», совет стал точнее |
| В кабинете сотрудника выводились технические поля `format: paper`, `copies: 1` | Скриншот кабинета сотрудника | Исправлены демо-данные, интерфейс показывает только поля из каталога |
| Третья карточка статистики висела одна на мобильном | Скриншот 360 px | Последняя карточка растягивается на всю ширину |

Автотест безопасности и сценариев (`scripts/e2e.sh`) — 15 проверок, все пройдены:
чужая заявка → 404, чужая справка → 404, без входа → 401, студент не меняет статусы → 403,
запрос без заголовка → 403, пароли — bcrypt, подбор пароля блокируется, полный путь
«подать заявку → сотрудник подтвердил → уведомление → справка с QR → проверка подлинности».
